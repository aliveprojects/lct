# Тестирование

## 1. Автоматические тесты

`npm test` — 240 тестов на Vitest (около 2 с): 90 сценарных и 150 случайных прогонов. Они проверяют игровую экономику без браузера: движок — чистые функции.

| Файл | Тестов | Что проверяется |
|---|---|---|
| `tests/plan.test.ts` | 8 | распределение бюджета: остаток, запрет превышения, подтверждение, неизменяемость плана, подсказка, добавление свободных монет в конверт |
| `tests/shop.test.ts` | 10 | покупки: списание, запись в историю, объяснение изменений, нехватка средств и варианты, баланс никогда не отрицателен, подтверждение перерасхода, украшения, ограничение показателей 100, список желаний |
| `tests/savings.test.ts` | 9 | накопления: взнос, ограничения, снятие только с подтверждением, «до → после» и срок по среднему взносу, исполнение мечты, своя цель |
| `tests/tasks.test.ts` | 28 | для **каждого** из 9 заданий: правильный вариант → 3 звезды и объяснение; ошибочный вариант → объяснение и путь исправления. Награды: один раз, доплата за улучшение; открытие по неделям и в демо; корзина, симулятор |
| `tests/period.test.ts` | 12 | итоги недели по формуле, регулярность, рост и стадия, пустая неделя не обнуляет прогресс, мягкая обратная связь, событие «Питомец чихнул», подарок дня, бонус взрослого |
| `tests/state.test.ts` | 8 | сохранение и восстановление, повреждённые данные, достройка полей, раздельные профили, календарь демо, сброс |
| `tests/scenario.test.ts` | 6 | сквозной сценарий Приложения А (шаги 2–12), 5 недель демо подряд: рост, смена стадий, все задания, целостность истории, детерминированность |
| `tests/fuzz.test.ts` | 150 | **случайные последовательности**: 150 детерминированных прогонов по 120 действий (покупки, взносы, снятия, недели, задания, события, бонусы). После каждого успешного действия проверяются инварианты (ниже); каждое отклонённое действие обязано ничего не менять и объяснять причину. Итог — 18 000 действий за 2 с |
| `tests/music.test.ts` | 2 | плейлист идёт по кругу, у треков есть автор и файл внутри приложения (без внешних адресов) |
| `tests/content.test.ts` | 7 | целостность контента, минимальный объём из п. 2.6, питомец-талисман Финни, валидатор |

Инварианты, которые проверяются на всех сценариях:

- баланс никогда не отрицателен; после каждой записи истории `баланс = сумма изменений`;
- **сохранение монет:** `кошелёк + накопления + цена исполненных мечт = все доходы − все покупки`;
- очки роста не убывают, показатели не опускаются ниже границы;
- исходный профиль никогда не изменяется функциями движка;
- `Σ очков по строкам итогов = очки недели`.

Дополнительные проверки:

```bash
npm run typecheck   # строгие типы TypeScript, включая неиспользуемые переменные
npm run contrast    # контраст 27 пар «текст / фон» темы «Космос» ≥ 4,5 : 1 (WCAG AA) — все проходят
```

| WebView | Chrome WebView 113.0.5672.136 |
| Итог | **32 из 32 проверок пройдено** |

| Аварийные завершения в `logcat -b crash` | ✓ нет |

Честные оговорки:

- Первый запуск на «холодном» эмуляторе (сразу после установки, пустые кэши) в ранних прогонах занимал 2–3,4 с до показа активности и до 6,8 с до содержимого вместе с накладными расходами теста. Повторные запуски — около 0,5 с. Причина — программная отрисовка эмулятора; на физическом устройстве замер нужно повторить.
- Отклик на нажатия вручную оценён как мгновенный, но точного измерения (≤ 1 с по ТЗ) на устройстве пока нет.
- Проверка на физическом устройстве с ОЗУ ≥ 3 ГБ **не проводилась**: команда должна прогнать `scripts/device-smoke.mjs` на реальном телефоне (`--serial <id>`) и добавить строку в таблицу.

### Как повторить

```bash
npm run release                                          # подписанные APK и AAB
FINNI_WEBVIEW_DEBUG=1 npx cap sync android \
  && (cd android && ./gradlew assembleDebug) \
  && cp android/app/build/outputs/apk/debug/app-debug.apk release/finni-1.0.0-debug-webview.apk
npx cap sync android                                     # вернуть конфигурацию без отладки WebView
node scripts/device-smoke.mjs                            # устройство или эмулятор должны быть подключены
```

Тестовая сборка с отладкой WebView нужна только для этого прогона и не публикуется; в релизном APK отладка выключена (`webContentsDebuggingEnabled: false`, проверено по `assets/capacitor.config.json` внутри APK).
