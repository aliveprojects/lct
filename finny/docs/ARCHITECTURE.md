# Архитектура

Серверной части нет: приложение целиком работает на устройстве, поэтому OpenAPI и схема развёртывания не нужны.

## Компоненты

```
┌──────────────────────────── Android (Capacitor) ─────────────────────────────┐
│  WebView                                                                     │
│  ┌──────────┐   действие   ┌──────────────────┐  Outcome   ┌─────────────┐   │
│  │ ui/      │ ───────────▶ │ app/store.act()  │ ─────────▶ │ domain/     │   │
│  │ экраны,  │              │ (единственный    │  (профиль  │ чистые      │   │
│  │ SVG      │ ◀─────────── │  путь изменения) │  + отчёт   │ функции     │   │
│  └──────────┘  состояние   └────────┬─────────┘  или       └──────┬──────┘   │
│       ▲                             │            ошибка)          │          │
│       │ учебные тексты              ▼                             ▼          │
│  ┌────┴─────┐               ┌────────────────┐            ┌──────────────┐   │
│  │ content/ │               │ app/persist    │            │ content/     │   │
│  │ JSON     │               │ platform/      │            │ (тексты и    │   │
│  └──────────┘               │ storage        │            │  цены)       │   │
│                             └───────┬────────┘            └──────────────┘   │
│                                     ▼                                        │
│                          SharedPreferences (Preferences)                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

| Слой | Папка | Что делает | От чего зависит |
|---|---|---|---|
| Игровая экономика | `src/domain/` | план, покупки, накопления, задания, периоды, рост, события. Только чистые функции: `(профиль, аргументы) → Outcome` | только от типов контента |
| Учебный контент | `src/content/` | данные в JSON + загрузчик и проверка целостности | ни от чего |
| Интерфейс | `src/ui/` | экраны, компоненты, иконки, питомец | domain, content, app |
| Состояние | `src/app/` | хранилище состояния, навигация, окна, сохранение | domain, content |
| Платформа | `src/platform/` | хранилище, звук, аппаратная кнопка «назад» | Capacitor |

Правило зависимостей: `domain` и `content` ничего не знают об интерфейсе и хранилище — поэтому вся экономика проверяется автотестами без браузера.

### Поток данных

1. Экран вызывает `act((профиль, ctx) => buy(профиль, 'meal', …))`.
2. Функция движка **не меняет** переданный профиль: копирует его и возвращает `Outcome`:
   - успех: новый профиль + `Report` — список изменений «что изменилось и почему» (баланс, накопления, показатель питомца, конверт плана) и совет, что делать дальше;
   - ошибка: код, объяснение и варианты выхода (`NOT_ENOUGH`, `CONFIRM_OVER_PLAN`, `PLAN_REQUIRED`…).
3. Стор сохраняет новый профиль (с задержкой 120 мс и немедленно при сворачивании приложения), экран показывает `Report` или объяснение ошибки.

Так реализованы принципы ТЗ: «сначала действие — потом последствие» и «баланс не меняется без объяснения» — любое изменение кошелька обязано вернуть отчёт и запись в истории.

Подтверждения — часть движка, а не только интерфейса: снятие из копилки без `confirmed: true` возвращает `CONFIRM_REQUIRED`, покупка «Хочется» сверх плана — `CONFIRM_OVER_PLAN`. Обойти их из интерфейса нельзя.

## Структуры данных

Полные типы — `src/domain/types.ts`. Всё состояние — простой JSON.

### Состояние приложения (`AppState`), ключ хранилища `finni.state.v1`

| Поле | Смысл |
|---|---|
| `schema` | версия схемы (сейчас 1) — для миграций |
| `settings` | `sound`, `animations`, `textScale` (`normal`/`large`/`xlarge`), `highContrast` |
| `introSeen` | показано ли знакомство |
| `mode` | `normal` или `demo` |
| `main`, `demo` | два независимых профиля: игровой и тестовый |
| `demoDayOffset` | сдвиг календаря в демо-режиме (дни) |

### Профиль (`Profile`)

| Поле | Смысл |
|---|---|
| `playerName`, `pet` | игровое имя и питомец: имя, внешний вид, показатели, очки роста, стадия, украшения, «причина» последнего изменения |
| `wallet` | баланс (доступные монеты), всегда ≥ 0 |
| `goals[]` | цели: цена, накоплено, взносы по неделям (`deposits`), исполнена ли |
| `activeGoalId` | текущая цель |
| `period` | текущая неделя: номер, подтверждён ли план, план, потрачено, отложено, заработано, покупки еды и ухода |
| `history[]` | итоги завершённых недель (`PeriodResult`): план, факт, очки по формуле, стадия до/после, строки объяснений |
| `ledger[]` | история монет: источник, сумма, изменение накоплений, баланс после операции |
| `tasks{}` | по каждому заданию: лучший результат (звёзды), число попыток, выплаченная награда |
| `wishlist[]`, `trophies[]` | список желаний, исполненные мечты |
| `pendingEventId`, `resolvedEvents[]` | непредвиденное событие |

Инварианты, которые проверяют тесты: баланс после каждой записи истории равен сумме сумм; баланс никогда не отрицателен; рост питомца не убывает; показатели не опускаются ниже нижней границы.

### Задание (`TaskDef`)

Задание — JSON с общими полями (`id`, `topic`, `title`, `skill`, `competencies`, `unlockPeriod`, `intro`, `rewards`, `learn`) и полями типа. Типы: `allocate`, `sort`, `cart`, `calc`, `sim`, `story`. Оценку выполняет `evaluateTask()` — одна чистая функция на тип; интерфейс лишь собирает ответ (`TaskAnswer`). Формат каждого типа — в `src/content/types.ts`, примеры — `src/content/tasks/*.json`.

### Сохранение и надёжность

- `platform/storage.ts`: на Android — `Preferences` (SharedPreferences), в браузере — `localStorage`.
- `parseState()` не падает на повреждённых данных: возвращает чистое начало, а испорченный текст сохраняется в резервный ключ. Поля, которых нет в старых данных, достраиваются значениями по умолчанию.
- Запись — при каждом изменении (с задержкой) и принудительно при `pause` / `visibilitychange` / `pagehide`.

## Добавление контента

| Что | Как | Менять код? |
|---|---|---|
| Новое задание существующего типа | положить `src/content/tasks/<id>.json` | нет — подхватывается автоматически (`import.meta.glob`) |
| Товар, цель, событие, термин словарика | добавить запись в соответствующий `src/content/*.json` | нет |
| Новый питомец, цвет, украшение | `pet.json` (+ рисунок в `ui/pet/PetSvg.tsx`) | только рисунок |
| Новый **тип** задания | тип в `content/types.ts`, оценка в `domain/tasks.ts`, экран в `ui/screens/Tasks.tsx` | да |

После добавления проверьте целостность: `npm test` (тест `content.test.ts` вызывает `validateContent`) и `npm run docs`, чтобы обновить карту контента.

## Демонстрационный режим

`AppState.mode = 'demo'` переключает активный профиль на тестовый (`state.demo`) — игровой профиль ребёнка не затрагивается. В демо-режиме `isUnlocked()` открывает все задания, а календарь можно «прокрутить» (`demoDayOffset`). Помощник `domain/demo.ts → playPeriodAuto()` проигрывает разумную неделю только через публичные действия движка, поэтому подчиняется тем же правилам, что и ребёнок. Тесты доказывают, что прогон из 5 недель детерминирован.

## Обновление учебного контента

Контент компилируется в приложение вместе с JSON, поэтому обновление — это выпуск новой версии приложения. Формат заранее отделён от кода: при желании контент можно подгружать из файла-пакета без изменения движка (см. план развития).
